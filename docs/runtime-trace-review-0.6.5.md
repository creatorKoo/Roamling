## 전체 차이 분류

모든 틱을 같은 단계·순번으로 정렬해 좌표·행동·이동 중 여부·클릭 허용·난수 카운터를 비교하고,
진단 로그의 전이를 대조했다. 행동 번호는 `BehaviorState.allCases` 순서다.

| 구간 | 비교 결과와 원인 |
|---|---|
| roam 300틱·cursor 180틱 | 모든 필드 동일 |
| lunge 19틱 | 5틱의 `lookAtPointer → idle`만 변경. 좌표·클릭 허용·난수는 동일. 잔여 속도가 있는 동안 꼬리 반응을 억제하는 `finish_tick::allows_pointer_glance` 규칙 |
| grab·held·drag·drop | 모든 필드 동일. 잡기와 끌기의 이동 경로·시점 유지 |
| land 90틱 | 몸체 위의 직접 클릭을 받는 28틱이 추가됨. 꼬리 반응 대신 idle 30틱·wander 11틱. 꼬리 반응이 배회를 붙잡지 않아 끝부분 위치 최대 7.69 차이와 난수 소비 변화 발생 |

| busy·review·ask·setback | 행동·이동·클릭 허용은 모든 틱 동일. 도착 좌표 약 0.84 차이와 앞 단계 난수 카운터 차이만 유지 |

화면 캡처는 녹화 시나리오에서 꺼져 있으므로 새 내용 회피 정책의 근거로 이 녹화를 쓰지 않는다.
그 정책은 `clearance_tests`가, 커서가 실제로 펫 위에 머무는 조건은 Rust의 600틱 검사와
수정한 `RuntimeLogicTests` 입력이 별도로 검사한다. 일반 테스트·릴리스 실행은 새 기준을
바이트 단위로 비교하며, 원본 녹화를 다시 만들거나 비교를 생략하지 않는다.
