# Mochi 시트 — 지금 무엇이 그려져 있는가

**as-built.** 이 문서는 현재 시트의 사실만 적는다. 무엇을 왜 그렇게 만들기로 했는지의
진단·계획·행별 목표는 `docs/history/mochi-v3-plan.md`에 있고, **계획과 결과가 갈린 곳이
있으므로**(아래 표) 행을 다시 만들기 전에는 계획표가 아니라 이 문서를 본다.

어휘는 `docs/state-contract.md`에서 고정됐고, 각 행이 언제·얼마나 오래 떠 있는지는
`docs/behavior-flow.md`에 있다. 아트 불변식은 `docs/art/mochi-animation-handoff.md`.

## 완료 — 실제로 만들어진 것

**2026-09-01 기준 14개 트랙 전부 승인됐고 빌드에 들어가 있다.**

정식 QA 게이트는 **57프레임 0실패**로 통과한다. 그 명령의 정식 호출은
`docs/history/mochi-v3-plan.md` 0.5절에 있다.

### 트랙

`인덱스`는 그려진 칸, `길이`는 실제 재생 길이다. 매니페스트와 `MascotPetFactory`가 같은
값을 들고 있고 테스트가 그걸 고정한다.

### 계획과 갈린 곳

행별 근거는 전부 `output/v3/approvals.json`의 `notes`에 있다. 아래는 무엇이 갈렸는가만
적는다 — **왜 갈렸는지는 그 파일이 정본이고, 여기 요약을 근거로 삼지 않는다.**

| | 2절 계획 | 실제 | 갈린 이유 |
|---|---|---|---|
| `gaze` | 확장 시트에 2칸 신규 | **표준 `review` 행을 다시 타이밍**해 빌린다. 새 칸 0 | 전용 행을 네 번 시도했지만 귀가 길어지며 고양이가 12~16px 커져 "긴장한 고양이"가 아니라 "큰 고양이"가 됐고 수염 수가 안 잡혔다. 대신 커서 거리가 재생 속도를 몬다 — 인지 범위 끝에서 느리고 잡히는 거리에서 두 배. 반려 후보는 `output/v3/bcuts/gaze-ears-perked` |
| `sleeping` | 4프레임 | 3프레임 | 생성된 네 번째 칸이 면적 11%·높이 4px 커서 등이 부푸는 게 아니라 고양이 전체가 부풀었다. 몇 분씩 도는 루프라 버렸다 |
| `sitting` | 2프레임 | 4프레임 | 꾸벅 한 번을 네 칸으로 — 눈 반쯤 감김 · 거의 감김 · 턱 떨굼 · 화들짝 |
| `caught` | 2프레임 | 4프레임 | |
| `stretching` | 계획에 없음 | **8프레임 신규** | `sleeping`이 들어오자 웅크린 자세에서 앉은 자세로 튀는 구간이 생겼다. 양 끝이 이웃 행과 맞아야 하는 유일한 행 |
| 확장 격자 | 8×2 | 8×3 | 위 프레임 수의 결과 |
| `pet.json` | `animations` 제거 | **남겼다** | `idle` 1.70초는 0번 칸을 12번 반복해야 나오는 길이라 프레임 목록 없이는 표현되지 않는다. 나머지 여덟은 표준 길이라 값이 같다 |

**확장 행은 프레임 수가 고정이 아니다.** Petdex 아홉 행은 렌더러가 앞 N칸만 읽으므로 수가
계약이지만(0절), 확장 행은 Roamling과 Codex만 읽으므로 3칸이든 8칸이든 된다.
