# 잠깐 숨기기와 끄기 발견성 (R2 · R3)

**상태: 구현됨 (2026-09-12). 사용자 실사용 확인 대기.** 요청 원문과 맥락은 `docs/requests.md`의
R2 · R3.

**실물 메뉴를 읽어서 확인했다.** 스크린샷은 이 기계에서 안 된다 — 캡처가 커서만 남기고 전부
검게 나온다(대화형 데스크탑 밖에서 도는 셸이라 그렇다). 대신 트레이 메뉴를 앱 자신의 경로로
띄우고(`WM_APP+1` + `WM_RBUTTONUP`), 뜬 `#32768` 창에 `MN_GETHMENU`를 보내 **살아 있는
HMENU를 그대로 걸어 다녔다.** 결과: `잠깐 숨기기`가 2번 항목, `고급`이 17번이고 그 안에 여섯이
전부, `Roamling 종료`가 20번(마지막). 고를 수 있는 항목만 세면 15개이고 종료가 15번째다 —
아래 §4의 숫자와 일치한다. 순서와 라벨을 보는 데는 이 방법이 스크린샷보다 정확하다.

## 1. 왜 둘을 같이 푸는가

같은 사람에게서 같은 날 나온 두 요청이고, 둘 다 **메뉴를 처음 여는 사람**의 문제다.

- **R2** "애들 잡도리할때 화면만 쳐다봄. **on.off 기능이 있었으면..?**"
- **R3** "다른건 안 눌러보고 **끄기를 못 찾았다고 함**"

**R3는 기능 결핍이 아니다.** 끄기는 있다(`menu.quit`). 못 찾은 것이다 — 지금 메뉴는 종료가
**맨 끝**이고 그 앞에 18줄이 있다(펫 · 크기 · 돌아다니기 · 포인터 피하기 · 잡기·끌기 · 일하는 앱 ·
동작 세부 설정 · agent 둘 · 커서 인식 · 시각적 배치 · 펫 폴더 · 진단 복사 · 펫 다시 읽기 ·
업데이트 셋 · 정보). 만든 사람은 훑어 내려가지만 처음 여는 사람은 그러지 않는다.

그래서 **R2의 새 줄을 어디에 두느냐가 곧 R3의 답이다.** 따로 풀면 메뉴가 한 줄 더 길어질 뿐이다.

## 2. "숨기기"의 뜻 — 창만 숨긴다 (사용자 결정 2026-09-12)

펫은 **그대로 살아 있고 보이기만 않는다.**

| | 숨긴 동안 |
|---|---|
| 틱 | 계속 돈다 |
| 위치·행동 | 계속 진행한다. 다시 켜면 그 사이 옮겨 간 자리에 있다 |
| agent 이벤트 | **계속 받는다** — 가려 둔 30초 사이의 턴을 잃지 않는다 |
| 지정 앱 선언 | 계속 낸다 (2초 만료가 있으므로 멈추면 좌석이 풀린다) |
| 화면 캡처(luminance) | **멈춘다** — 안 보이는 펫의 자리를 고르려고 62 ms를 쓸 이유가 없다 |
| 클릭 | 안 받는다. 숨긴 창이 클릭을 먹지 않도록 상호작용도 같이 끈다 |

**`stop()`을 재사용하지 않는다.** 그것은 수신기·타이머·관찰자를 전부 내린다
(`RoamlingRuntime.stop()`). 30초 가리는 용도에 그건 과하고, 가린 사이의 일을 잃는다.

**재시작하면 다시 보인다.** 숨긴 상태를 설정에 남기지 않는다 — 남기면 다음 실행에 "앱이 안
떠요"가 되고, 그건 R3보다 나쁜 발견성 문제다.

## 3. 어디에 사는가 — 코어

`set_roaming_enabled` · `set_pointer_avoidance_enabled` · `set_interactions_enabled`가 전부
`rust/roamling-core/src/pet_runtime.rs`에 있고 **각자 자기 후속 처리를 들고 있다**(걷던 경로
취소, 잡기 해제). 숨기기도 같은 성격의 스위치이므로 같은 자리다.

- `pet_runtime.rs` — `set_hidden(&mut self, hidden: bool)`. 숨길 때 잡기를 해제하고
  luminance 요청을 내지 않는다.
- 셸은 **결과만** 쓴다 — macOS `overlay.setVisible(false)`, Windows `ShowWindow(hwnd, SW_HIDE)`.

**seam은 이미 있다.** `OverlayProviding.setVisible`
(`Sources/RoamlingCore/PlatformServices.swift:143`)이고 macOS는 `orderOut`으로 구현돼 있다
(`PetOverlayPanel.swift:259`). 지금 그걸 부르는 곳은 `start()`/`stop()`뿐이다. Windows는
`tuning.rs`에 `ShowWindow(SW_HIDE)` 선례가 있다.

## 4. 메뉴 — 아직 정하지 않은 것

`MenuAction`은 닫힌 열거형이라 case를 하나 더한다(`toggleHidden`). macOS는 `ShellMenu`가
트리를 값으로 들고, Windows는 `tray.rs`가 같은 모양을 따로 들고 있으므로 양쪽에 줄을 넣는다.
문자열은 en·ko 두 파일에 같은 키로 넣는다.

**배치: 숨기기를 맨 위에, 드문 항목을 하위 메뉴로 접는다 (사용자 결정 2026-09-12).**
종료는 **관례대로 맨 끝에 남기되**, 그 앞을 짧게 만들어 눈에 들어오게 한다.

**"숨기기와 종료를 둘 다 맨 위에" 는 버렸다.** 가장 확실히 보이지만 두 줄이 붙어 있어
**잘못 누르면 가리려다 앱이 꺼진다** — 비개발자에게는 못 찾는 것보다 그쪽이 나쁘다. 되돌릴
방법도 없다.

바뀐 최상위 트리 (macOS 기준, Windows `tray.rs`도 같은 모양):

```text
Roamling — Mochi            (캡션)
─────
잠깐 숨기기                  ← 새 줄. 체크 표시로 상태를 보여준다
─────
펫 ▸ · 크기 ▸
─────
돌아다니기 · 포인터 피하기 · 잡기·끌기 · 일하는 앱 ▸ · 동작 세부 설정…
Claude Code ▸ · Codex ▸
커서 인식 ▸ · 시각적 배치 ▸
─────
고급 ▸                       ← 새 하위 메뉴
─────
Roamling 정보 · Roamling 종료
```

`고급 ▸` 안으로 들어가는 것: 펫 폴더 열기 · 진단 기록 복사 · 펫 다시 읽기 · 업데이트 확인 ·
로그인 시 시작 · 자동 업데이트. 전부 **한 번 정하고 다시 안 여는 것들**이다.

**업데이트가 받아진 상태의 캡션(`status.update.ready`)만은 최상위에 남긴다.** 그건 설정이
아니라 알림이고, 접어 두면 아무도 못 본다.

**세는 단위를 분명히 한다 — 캡션과 구분선을 뺀 "고를 수 있는 줄"이다.** 행 수와 선택 항목
수를 섞으면 숫자가 안 맞는다(처음 이 문서가 그렇게 틀렸다).

| | 고를 수 있는 줄 | 종료는 몇 번째 |
|---|---|---|
| 전 (agent 둘) | 19 | 19번째 |
| 후 (agent 둘) | **15** | **15번째** |
| 후 (agent 없음 — 하네스) | 13 | 13번째 |

숨기기가 하나 늘고 여섯이 `고급 ▸` 하나로 접히므로 순증은 −4다. agent 수만큼 달라지므로
**테스트가 고정하는 13은 agent가 없는 하네스 구성의 숫자다.** 어느 쪽이든 종료 바로 위는
`정보`다.

새 문자열 키 둘: `menu.hide` · `menu.advanced`. en·ko 두 파일에 같은 키로 넣는다.
Windows 명령 id는 비어 있는 `16`을 쓴다(1~9·11~15 사용 중, 20~23 크기, 100~119 agent,
200~ 일하는 앱, 1000~ 펫).

## 5. 검증

메뉴 트리 테스트의 집은 **`Tests/RoamlingLogicTests/ShellLogicTests.swift`**다. 거기 두 군데가
함정이다 — `switches` 표(토글이 거기 등록돼야 체크 상태가 검사된다)와 **`asks` / `doesNotAsk`
목록**. `MenuAction`은 닫힌 열거형이라 case를 더하면 그 분류에 넣어야 하고, 빠뜨리면 조용히
검사에서 새거나 테스트가 깨진다.

- 하네스에서 메뉴 트리는 값이므로 **화면 없이 테스트된다** — 숨김 상태에서 줄의 체크가
  따라오는지, **종료가 몇 번째 줄인지**까지 고정할 수 있다. R3는 그 숫자가 전부이므로
  테스트도 그 숫자를 고정한다.
- `고급 ▸`으로 접은 여섯 항목이 **여전히 도달 가능한지** — 접는 것과 잃는 것은 다르다.
- 숨긴 동안 agent 이벤트가 유실되지 않는지 — 하네스에서 숨기고, 이벤트를 넣고, 다시 켜서
  좌석이 살아 있는지 본다.
- 숨긴 동안 luminance 요청이 0인지.
- `RuntimeTrace.txt`는 바뀌면 안 된다. 숨기기는 새 스위치이고 기본값은 꺼짐이므로, 녹화된
  세션의 어떤 판정도 뒤집히지 않아야 한다.

**Swift는 이 기계에서 컴파일되지 않는다.** 이번에는 그걸 CI가 메운다 —
`gh workflow run check-macos.yml --ref <branch>`가 `./scripts/test.sh`를 돌린다(2026-09-12에
W8이 그렇게 검증됐다). Windows 쪽은 `.\scripts\test.ps1`로 여기서 바로 확인한다.
