# 쌀 실시간 팔레트

## 현재 메뉴·재시작 흐름 (2026-10-04)

보리와 쌀은 승인 프리셋만 선택한다. 색 직접 고르기 창·시스템 색 피커·Shift/Option 진입은 제거한다.
아래 색 조절 창 관련 기록은 과거 구현이다. 단일 원본과 공유 리컬러 연산은 그대로 사용한다.
Windows `main.rs`의 시작 경로는 저장된 패키지/내장 종류를 복원하고 쌀 팔레트를 입힌 뒤,
보리 팔레트는 `current_package.is_none() && ssal_source.is_none()`일 때만 복원해야 한다.
`settings.rs::set_ssal_palette`는 기본 쌀의 색 키만 지우며 `builtInPet=ssal`은 유지한다.
기본 쌀 및 8색을 실제 새 프로세스에서 승인 팔레트의 픽셀·트랙·메뉴 선택과 비교한다.
회귀 검사는 디버그 빌드 후 `scripts/test-ssal-restart.ps1 -Exe <debug roamling.exe 경로>`로
실행한다. 임시 APPDATA만 사용하며 실제 사용자 설정은 읽거나 바꾸지 않는다. 수정 전에는
`restarted Ssal standard pixels` 단언에서 실패하는 것을 재현했다.

## macOS 연결 설계 (2026-10-05)

- `MascotPetFactory.make(.ssal)`은 `petResourceBundle`에서 승인한 두 매니페스트와 두 시트를 읽고 `PetLoader`의 레이아웃/트랙 검증을 재사용한다. 새 시트나 Swift 타이밍 표를 만들지 않는다.
- `ffi/palette.rs`에 쌀 프리셋·기본값·시트 객체를 추가한다. 기존 FFI 서명은 유지한다. `ssal::Source`가 Windows와 같은 영역과 색 계산을 수행한다.
- `RoamlingRuntime`은 `roamling.palette`와 `roamling.ssalPalette`를 분리한다. 시작/종류 전환 시 해당 펫의 시트만 적용하고, 쌀의 색 전환은 player를 재시작하지 않는다.
- `ShellMenu`에서 보리·쌀 각각 승인 프리셋을 노출한다. `fat-mochi` 저장 선택은 `.ssal`로 이전하며 외부 패키지 선택은 보존한다. FatMochi 전용 리소스와 생성 코드는 제거한다.
- 검증은 공유 FFI의 Windows 결과 일치, Swift 하네스의 내장/외부 패키지 동작 일치·9색 저장 복원·기본 쌀·이전 설정 이전·메뉴 검사를 포함한다. macOS 빌드/실행은 가능한 환경에서 별도로 확인하며 Windows 테스트 결과로 대체하지 않는다.

## 승인본: 9색 눈 구분 보강 (2026-10-04)

2026-10-05 macOS 연결 검증: 공유 Rust와 Windows 게이트 통과, `rust/roamling-pet/tests/ssal_ffi.rs`에서
Swift에 전달할 9색 표와 두 시트 픽셀이 Windows 경로와 같음을 확인했다. Swift/Kotlin 바인딩 생성도
통과했다. `PetLogicTests`, `TuningPersistenceTests`, `ShellLogicTests`의 쌀 회귀 검사는 추가했지만
Swift/macOS SDK가 없는 현재 기계에서 실행하지 못했다. macOS의 `scripts/test.sh`와
`scripts/build-app.sh release` 및 실제 메뉴·재시작 확인을 통과하기 전에는 macOS 실행 검증 완료로 보지 않는다.

통과했다. 사용자는 외부 게시 대신 비교 PNG 한 장을 선택했으며
`eye-refinement-v2/eye-colour-review.png`로 전달한다. 앱 설치·설정은 이번에 바꾸지 않았다.

## 승인된 범위와 흐름

내장 연결은 `BuiltInPets/ssal-*`의 중립 원본 두 장·매니페스트 두 개를 Rust 실행 파일에
포함하고, 기존 매니페스트 해석 함수로 `PetAsset`을 만든다. 설치 폴더에 시트를 풀거나
사용자 외부 펫을 덮어쓰지 않는다. Windows는 기존 `roamling.builtInPet` 키로 보리/쌀
선택을 저장하고, 쌀 원본 캐시와 9색 연산은 외부 패키지와 같은 경로를 사용한다.
보리 전환은 기존 팔레트로, 쌀 복귀는 쌀의 마지막 팔레트로 돌아간다.

2026-10-04 후속 통합: 승인된 9색을 `ssal::PRESETS`에 등록하고 트레이 명령 범위를
배열 길이에 맞춘다. `WHITE`는 검증용 원본 복원 상수로 유지하고 메뉴·설정 기본값은
호두색 눈을 포함한 `DEFAULT`로 분리한다. 사용자 지정 눈 값은 기존 직렬화 그대로
읽으며, 쌀 쌀/처음으로 선택만 승인 기본값으로 돌아간다. 색 변경은 기존
`main.rs::apply_palette`의 이미지 교체 경로를 사용한다.

사용자는 흰 쌀 원본 한 벌을 보리처럼 실시간으로 칠하고 검은 쌀부터 확인하기로 했다.
색별 이미지 추가가 아니라 팔레트 숫자만 저장한다. 초기에는 Windows 외부 펫
`ssal-white`로 검토했으며, 현재 Windows 코드는 내장 쌀과 승인된 9색을 제공한다.
2026-10-05 macOS 쌀 연결과 FatMochi 제거 코드를 반영한다. macOS 실기 검증과 Android 연결은 남는다.

`roamling-win/main.rs::apply_palette`는 쌀 원본 캐시가 있으면 쌀의 이미지 두 장만
교체한다. 보리 색 메뉴는 먼저 보리로 전환한 뒤 보리 팔레트를 적용한다. 애니메이션 resolver/player는
색 변경 때문에 재시작하지 않는다. `package::load`로 읽은 프레임·동작 계약은 유지한다.

구현 흐름은 패키지 원본 읽기 → 공유 Rust 코어의 쌀 영역 구분 1회 → 팔레트 변경 시
원본으로부터 다시 색 계산 → 렌더 이미지 교체 → `roamling.ssalPalette`에 숫자 저장이다.
보리의 `roamling.palette` 값은 유지한다. 쌀 쌀 선택은 승인된 흰 털·호두색 눈으로 복원하고
기본 팔레트 저장 값을 지운다. 내부 `WHITE` 상수만 원본 바이트 복원 검증에 쓴다.
프리셋의 털색과 눈 색은 `Palette.eye`와 기존 저장 형식을
재사용하며, `ssal::Source`가 시트의 눈 범위와 원본 명도로 홍채 내부만 구분한다.
`ssal/eyes.rs::bounds`는 현재 v13 자세의 눈 영역이며 동공·테두리·흰 반사점은 보존한다.
선택한 눈 색은 털색과 독립적으로 계산한다. 기존 눈 설정값은 원래 렌더링을 유지한다.

흰 쌀은 보리와 다른 저채도 단색 털이다. 보리 전용 무늬/몸통 명도 분류를 그대로
적용하면 귀·혀·눈 반사까지 변한다. 같은 `pet_image` 모듈과 `PaletteTargets`를 사용하되
쌀의 털과 보존 영역을 따로 분류한다. 색 계산은 Rust 한 곳에 두며 Python은 검토 이미지
배치에만 사용한다. 기존 보리 연산자와 프리셋은 변경하지 않는다.

## 검증 계획

- 실제 v9 원본의 알파·셀 위치·76프레임·동작 시간표 불변.
- 흰색 복원이 원본 렌더 바이트와 동일하고 분홍 혀·눈 반사가 검정에서 보존됨.
- 같은 원본을 반복 칠해도 누적 손상 없음.
- 설정 저장·재시작·보리/다른 펫 전환 시 팔레트가 섞이지 않음.
- 실제 Rust 출력으로 작은 크기 검은 쌀 미리보기 생성.
- Windows 테스트 게이트 및 실행 확인. macOS/Android는 이번에 연결하거나 검증했다고 주장하지 않음.

## 구현 위치와 사용법

- `roamling-core/src/pet_image/ssal.rs::Source`: 흰색 원본 및 분홍 영역·눈 반사 보존 맵을
  캐시한다. `image`는 매번 원본에서 계산하고 기존 `from_hls`를 사용한다. `WHITE`는 원본
  렌더 바이트 그대로, `BLACK`은 별도 이미지 없는 팔레트 상수다. 작은 밝은 섬을 눈 반사로
  보존할 때 v9 각 자세의 얼굴 범위(`in_head`)를 함께 검사한다. 발끝의 밝은 털까지 반사로
  잘못 보존하는 사례를 전체 시트 검토에서 발견해 이 조건을 추가했다. 자세를 바꾸면 해당
  영역도 실제 출력에서 다시 확인해야 한다.
- `roamling-pet/src/package.rs::SsalPalette`: `ssal-white`의 표준 8×9·확장 8×3 원본을
  읽는다. `apply`는 이미지 두 장만 바꾸며 셀 크기·동작 목록·시간표는 손대지 않는다.
- `roamling-win/src/main.rs::apply_palette`, `adopt`: 쌀의 현재 패키지를 유지한 채 칠하고
  보리 전환 후 돌아오면 쌀 색을 복원한다. 펫을 바꿀 때 이전 색 조절 창과 대기 이벤트를 닫는다.
- `roamling-win/src/settings.rs::ssal_palette`, `set_ssal_palette`: 보리와 독립된
  `roamling.ssalPalette` 숫자를 저장한다. 기본 흰색 선택은 이 키를 삭제한다.
- 트레이 **펫 → 쌀 (기본 제공) → 승인된 9색 / 색 고르기**. 쌀의 색 고르기는 Shift 없이 열리고
  `palette_debug.rs::build`에서 털색·눈 색 축을 표시한다. 보리 메뉴와 프리셋은 기존대로다.

## 실제 경로 확인

`roamling-pet/examples/ssal_palette_review.rs`는 앱과 같은 `SsalPalette::apply`로
실사용 v9 원본을 검정 → 흰색 → 검정 순서로 칠한다. 전체 알파·분홍색·시간표 보존,
정확한 흰색 복원, 반복 검정 결과 일치를 검증한다. Python 미리보기는 해당 Rust 출력의
배치와 축소만 한다. 산출물은 `output/ssal-live-review/`.

코어의 반투명 픽셀·눈 반사·OS 색 피커용 `aimed_at` 검사와 Windows의 설정 재로드·메뉴·
실제 숨겨진 색 조절 창 검사가 통과했다. debug 앱의 `ROAMLING_SSAL_PALETTE_SMOKE=1`은
실제 메뉴 명령 함수에서 검정/흰색 복원과 보리 전환·복귀를 확인한다. 반드시 임시 APPDATA와
`ROAMLING_SMOKE_TEST=1`을 함께 사용한다(`output/smoke-ssal.ps1`). 사용 중인 설정은 이
검사에 쓰지 않는다. 검정 출력의 `pet_qa.py`는 76프레임 0실패다.

## 실사용 v10 애니메이션 조정 (2026-10-02)

커서 근처의 좌우 두리번거리기가 부산스럽다는 피드백으로 외부 패키지 `gaze`를 정면에서
쉬다가 한쪽을 보고 돌아오는 4초 트랙으로 변경했다. 공통 거리별 가속을 적용하면 실제
2~4초이며, 이전 0.515~1.03초보다 느리다. 에이전트 관찰·쓰다듬기 갸웃은 그대로다.

땅파기 전신 6장은 v8 해상도 원본에 v9 혀 색 보정을 재적용한 뒤 85%로 한 번만 축소했다.
v9의 90% 대비 약 5.6% 작아진다. 지면 175·820ms 리듬·원래 색을 유지하며, 나머지
90개 셀(빈 셀 포함)은 v9와 바이트가 같다. 흰 원본 한 벌과 같은 실시간 색 경로를 사용한다.

`output/ssal-polish-v10/`에 재현 스크립트·흰색 패키지·실제 Rust 출력 비교 GIF·검증 기록이
