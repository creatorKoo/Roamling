# 상태형 source — 상위 설계 (2026-09-12)

**상태: 1·2단계 구현 완료 (2026-09-12), 실사용 확인 대기.** 상태 층은
`rust/roamling-core/src/source_state.rs`에 있고, 일하는 앱이 그 위로 옮겨졌다. 지금까지
무엇이 실렸는지는 §8을 본다. 3단계(실사용 확인) 전에는 영상·게임으로 넘어가지 않는다.

`docs/history/focus-activity-flow.md`는 **2단계 이전 구조**를 설명하는 문서다 — 그 문서의 우회 코드
목록이 여기서 지운 것들의 출처이지만, 인용 검증이 중단된 상태이므로 근거로 쓸 때는 코드를
다시 본다.

## 1. 왜

`ActivitySourceType`에 `agent · game · media · system · custom`이 있지만(`Sources/RoamlingCore/Activity.swift`),
그 값을 보고 다르게 행동하는 코드는 2026-09-11까지 없었다. director는 생산자가 agent 훅 하나뿐이라는
전제로 만들어졌다. 일하는 앱은 성격이 다른데 그 계약에 맞춰 넣느라 **우회 장치가 열 개** 붙었다
(`docs/history/focus-activity-flow.md` §4).

영상·게임도 같은 성격이다. 지금 구조에 그대로 얹으면 우회가 세 벌이 된다. 그래서 source를 먼저 두
종류로 나눈다.

## 2. 두 종류

| | 사건형 (event-shaped) | 상태형 (state-shaped) |
|---|---|---|
| 예 | Claude Code · Codex 훅 | 일하는 앱 · 영상 재생 · 게임 |
| 성격 | 순간에 일어난 사건 | 계속 유지되는 상태 |
| 지금 | `CompanionEvent` 그대로 유지 | 이벤트를 흉내 내는 중 (우회의 원인) |
| 앞으로 | **변경 없음** | 상태를 선언하는 새 경로 |

사건형은 손대지 않는다. 훅은 지금도 자연스럽게 맞고, 바꾸면 픽스처·녹화 세션이 전부 흔들린다.

## 3. 상태 낱말

셸/source가 도메인 사정을 번역해서 **공용 낱말**로 올린다. "타이핑 중"이 아니라 "활동 중"이다.

| 낱말 | 뜻 |
|---|---|
| `없음` | 지금 펫이 여기 있을 이유가 없다 |
| `곁에 있음` | 사용자가 여기 있지만 무언가 하고 있지는 않다 |
| `활동 중` | 지금 하고 있다 |
| `잠깐 멈춤` | 하다가 멈췄다 |

함께 올리는 것: **어디**(창 위치 힌트) · **누구**(source id) · **종류**(work app · media · game).

도메인 타이밍(10초 창, 3초 유예, 2분 세션, Cmd-Tab 키 제외)은 **source 안에 남는다.**

## 4. 선언 방식

- 셸이 샘플마다(0.5초) 현재 상태를 **선언**한다. 이벤트를 쌓지 않는다.
- **같은 상태를 다시 선언하면 아무 일도 일어나지 않는다.** 반응은 상태가 **바뀔 때만** 한 번.
- **갱신이 끊기면 만료된다** — 셸이 죽거나 창을 잃으면 자동으로 `없음`. 재발신·heartbeat가 필요 없다.
- 좌석 유지, 우선순위, 쉬는 펫 처리, 마무리 반응은 **director 몫**이다.

## 5. 우선순위

1. **사건형 > 상태형.** agent가 자리를 지키는 동안 상태형은 자리를 못 가져간다(2026-09-11 결정 유지).
2. **사용자 답을 기다리는 agent 신호는 최상위.** 지금과 같다.
3. **상태형끼리는 포커스를 가진 쪽이 이긴다 (사용자 결정 2026-09-12).** 영화를 눌러서 보고 있으면
   문서를 띄워 놨어도 영화, 문서를 눌러서 쓰고 있으면 영상이 돌아가도 문서다. 선언에 "지금 포커스를
   가졌는가"가 함께 온다. 포커스를 가진 상태형이 없으면 `활동 중` > `잠깐 멈춤` > `곁에 있음`,
   그래도 같으면 최근에 바뀐 쪽.
4. 상태형은 attention의 **점수 경쟁에 참여하지 않는다.** 층이 다르다 — 점수·이력 여유·쿨다운은
   사건형끼리의 규칙으로 남는다. 구현됨: 상태 선언은 `declare_state`로 들어가고 attention을
   거치지 않는다. agent와의 우선순위만 `agent_on_duty` 한 술어로 판정한다.

## 6. director가 새로 맡는 것 (2026-09-12 구현됨)

source에서 director로 옮겨온 것들. 각각 옮기기 전에는 일하는 앱 안의 우회 장치였다.

선언에는 상태와 함께 **이정표**(`sitting_started` · `sitting_ended`)가 실릴 수 있다. "이번 활동이 한
자리의 시작인가", "그 자리가 끝났고 마무리할 만한가"는 source만 아는 도메인 판단이고(2분 세션·3분
타이핑), **그 이정표에 어떤 그림을 붙일지는 core의 표 한 곳**이 정한다. 그래서 인사 점프와 손 흔들기가
source에서 사라진다.

| 옮겨온 책임 | 없어진 우회 장치 |
|---|---|
| 상태가 유지되는 동안 좌석 유지, 갱신 끊기면 만료 | 60초 heartbeat · 15초 막힘 재발신 · 매 이벤트 새 id |
| 상태 전이에서만 반응 한 번 | `Present` kind · 도착 반응 재장전 대응 |
| 쉬는 펫이면 상태만 보관, 깨면 반영 | 쉬는 중 보류(`news_owed` · `pet_resting` 입력) |
| `없음` 전이에서 마무리 반응 한 번 | 손 흔들기 뒤 자리 비움 보류 · `agent_on_duty` 입력 |
| 걸어가는 중 반응이 덮이지 않게 도착까지 보장 | 인사 대기(`dispatched_event` · `arrival_pending` 입력) |

남는 것: Cmd-Tab 규칙과 nil 규칙. 둘은 director 탓이 아니라 플랫폼 API 사정이다.

## 7. (종류 × 상태) → 그림

표는 core 한 곳에 둔다. source가 "어떤 이벤트를 보낼까"를 고르지 않는다.

| | 곁에 있음 | 활동 중 | 잠깐 멈춤 | 전이 |
|---|---|---|---|---|
| 일하는 앱 | 옆에 앉아 idle | `running` (일하는 그림) | `waiting` (갸웃) | 첫 활동에 점프, `없음`에 조건부 손 흔들기 |
| 영상 | 화면 근처 idle | 조용히 보기 (`review`) | idle | 없음 |
| 게임 | — | **방해 금지** (자리 안 잡음) | — | 없음 |

영상·게임의 세부는 붙일 때 정한다. 지금 정할 것은 "상태형이면 이 표 한 곳에서 정해진다"까지다.

### 8.1 2단계에서 실제로 지운 것

일하는 앱 source가 director의 사건형 기계를 상대하려고 들고 있던 것들이다. 상태 선언은
"지금 이렇다"를 매 샘플 다시 말하므로, 한 번 보낸 것이 도착했는지 세어 둘 이유가 사라졌다.

| 지운 것 | 무엇이었나 | 왜 없어도 되나 |
|---|---|---|
| `HEARTBEAT` (60초) | 좌석을 지키려고 `Present`를 매분 재발신 | 선언이 0.5초마다 갱신된다. 안 오면 `STATE_EXPIRY` 2초로 만료 |
| `BLOCKED_RESEND` (15초) · `SeatNews` | agent에 막힌 동안 다시 말하기 | 막혀도 선언은 계속 갱신되고, agent가 놓으면 그 다음 샘플에 이긴다 |
| `news_owed` · `pet_resting` | 쉬는 펫에게 간 소식이 버려지는 것을 막기 | director가 전이를 보관한다(`state_transitions`) |
| `Greeting` · `GREETING_DELAY` · `GREETING_TIMEOUT` | 점프가 보이기 전에 running이 덮는 것을 막는 박자 | 점프는 전이 반응(1회), running은 유지 반응. 구조가 순서를 지킨다 |
| `Goodbye` · `WAVE_HOLD_TIMEOUT` | 손 흔들기가 나간 뒤 자리 비움을 붙잡아 두기 | 작별은 `SittingEnded` 이정표 하나이고 좌석 반납과 같은 전이다 |
| `dispatched_event` · `arrival_pending` · `pet_resting` · `agent_on_duty` (셸이 넘기던 펫의 사실 넷) | 위 박자·보관·거르기의 입력 | 전부 director 안의 사실이라 셸을 거칠 이유가 없다 |
| `TYPING_INTENSITY` · `PRESENT_INTENSITY` · `WAVE_INTENSITY` | attention 점수를 겨루려고 붙이던 세기 | 상태형은 점수로 겨루지 않는다. 포커스가 이긴다(§5) |
| 이벤트별 id | 무엇이 도착했는지 대조하려고 | 대조할 것이 없다 |

`focus_activity.rs`는 2,489줄에서 463줄로 줄었고, 남은 것은 상태 기계와 그 상수 다섯
(`TYPING_WINDOW` · `WAITING_BEFORE_RELEASE` · `FOCUS_GRACE` · `BREAK` · `WAVE_AFTER_TYPING`)뿐이다.

`CompanionEventKind::Present`는 **아무도 만들지 않게 됐지만 지우지 않았다** — kind가 FFI를
인덱스로 건너서 differential 픽스처 10개가 위치로 이름을 부르기 때문이다(`activity.rs`에 사유 주석).

### 8.2 2단계 합격 확인

- `./scripts/test.sh` exit 0, 하네스 184개 전부 통과, cargo 경고 0.
- `RuntimeTrace.txt` 바이트 불변, differential 픽스처 무변경 — 사건형 경로를 안 건드렸다는 뜻이다.
- 하네스 단언은 하나도 고치지 않았다. 다만 `the first keystroke hops, ten quiet seconds ask,
  and five more give the seat back`의 **가짜 키보드는 고쳤다.** 그 fake는 "마지막 키가 N초 전"을
  샘플마다 같은 값으로 답해서, 시계가 가면 마지막 키도 같이 앞으로 밀렸다 — 멈춘 키보드가 늙지
  않는다. 옛 코드는 그 어긋남 위에서 우연히 통과했다: 인사 박자 0.84초가 모든 구간을 0.7초씩
  뒤로 밀어, `key=9`인 샘플 하나가 마침 앱이 앞에 온 시각 직후로 떨어지면서 "마지막으로 센 키"가
  1000.1초로 다시 찍혔고, 그로부터 10초가 질문의 근거였다. 박자를 지운 지금은 그 샘플이 없다.
  이제 fake는 `lastKeyAt`을 들고 시계와 함께 멈춤이 자라며(`RuntimeLogicTests.swift`), 테스트는
  진짜 규칙 — **앱에 친 마지막 키로부터 10초** — 을 고정한다. 규칙 자체는 옛 코드와 같다.

## 9. 영향 범위와 검증

- **Swift 대조군** — director를 바꾸면 `SwiftActivityDirector`도 같이 바꾸고
  `CoreLogicTests`의 Swift↔Rust 대조가 둘을 비교한다.
- **differential 픽스처** — 기록된 호출을 재생한다. 사건형 경로를 안 건드리는 것이 목표이고,
  **픽스처는 재생성하지 않는다.** 바뀌면 그건 사건형에 영향을 줬다는 뜻이다.
- **녹화 세션** — `RuntimeTrace.txt`가 바이트 불변이어야 한다.
- **Windows** — 같은 core를 쓰므로 director 변경은 자동으로 간다. 일하는 앱 배선(W8)은 새 API로 한다.
- **실기** — macOS에서 서명 빌드로 확인. 진단 로그로 상태 전이가 보이게 한다.
